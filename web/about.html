Your workspace, grown on your own ground.

Notes, tasks, calendar, bookmarks, feeds, contacts, secrets, files, media and a blog. Everything private is encrypted in your browser and kept on one small server that you run. The server only ever holds ciphertext.

What it holds

One login, the things you actually keep.

Each part is a plain encrypted collection. The same account works in the web app, the command line and the SDK.

vaultNotes

Markdown, tags and checklists, with a distraction-free editor.

tasksTasks

A Kanban board with priorities, due dates and links to notes.

calendarCalendar

Events and an agenda, linked to your notes.

bookmarksBookmarks

Folders and tags. Import and export from Brave, Chrome and Firefox.

feedsFeeds

Follow blogs and news over RSS or Atom. Your list is encrypted, OPML in and out, read inside Orto. Your own blog has a feed too.

contactsContacts

An address book with vCard import and export.

secretsSecrets

Passwords, API keys and secure notes, hidden by default, with a generator.

files · photosFiles & Photos

Encrypted uploads in folders, and a photo grid with albums. Big files go up in encrypted chunks.

mediaMusic & Video

Play your own files while they stream: encrypted in chunks, decrypted in your browser, with playlists and seeking.

/s/<id>#keyPublic links

Share a note or file. The key lives only in the link, so the server cannot read it. Revoke any time.

/blog/youBlog

Optional public posts in Markdown, with an RSS feed. The one thing stored in the clear on purpose.

How it stays private

The key never leaves your browser.

Derive

Your username and password become two secrets with PBKDF2 (210,000 rounds, SHA-256): one encryption key and one login secret.

Encrypt

Every private record and file is sealed with AES-GCM 256 in the browser before it is sent.

Store

The server keeps ciphertext, and only a hash of the login secret. It cannot read your data, even if it wants to.

The server can see

  • usernames, record ids and timestamps
  • collection names and file sizes
  • your IP address (as any web server does)
  • public blog posts, because you published them

Good to know

  • There is no password recovery. Lose the password and the data is gone.
  • Put it behind HTTPS before exposing it.
  • Registration is open by default; set ORTO_REGISTRATION=closed once your accounts exist.
  • The app loads nothing from other sites: scripts, icons and fonts are served by your own server.
  • Optional tag and emoji suggestions run small models in your browser (Gist and Emo by Desert Ant Labs). Off by default, installed by the admin, and your text is never sent anywhere.

Run it

One small server, one SQLite file.

Node 22.5 or newer (it has SQLite built in). Your data lives in a single data/ folder: back that up and you have backed up everything.

Desktop app, nothing to install

Desktop zips (Windows, macOS, Linux; Node included, no install): unzip the one for your system from the latest release and run Orto.cmd, Orto.command or Orto.sh. It starts a local server and opens the browser. Data goes in your user folder (%APPDATA%\Orto, ~/Library/Application Support/Orto or ~/.local/share/orto).

One line, no clone, no Docker

npx -y -p github:scobru/orto orto-server

Docker

git clone https://github.com/scobru/orto.git && cd orto
docker compose up -d --build

From a clone

git clone https://github.com/scobru/orto.git
cd orto && npm start

Then open http://127.0.0.1:8787, choose a username and password, and the app offers to create the account. Settings are environment variables:

PORT / HOSTlisten address, 8787 on 127.0.0.1 by default
ORTO_DATAwhere the database and uploads live (./data)
ORTO_REGISTRATIONopen or closed
ORTO_QUOTA · ORTO_MAX_UPLOADper-user storage (5 GB) and largest file (200 MB)
ORTO_ADMIN_PASSturns on an admin panel at /admin to change those settings, manage users and make backups

For scripts and agents

The same data, from the command line.

A dependency-free JavaScript SDK and a CLI use the same login. Autonomous agents can keep their notes, tasks and files in an encrypted workspace you control. For Claude Desktop and other MCP clients there is a small local MCP server (orto-mcp): it runs on your machine, so the encryption stays there.

node cli.js vault-write --title "Idea" --body "- [ ] ship it"
node cli.js file-upload --file report.pdf --folder Docs/2026
node cli.js file-list --folder Docs --table
node cli.js secret-add --name GitHub --generate
import Orto from './orto.js';
const os = new Orto({ server: 'http://127.0.0.1:8787' });
await os.login('alice', 'secret');
await os.writeVaultNote({ title: 'Hi', body: 'Encrypted.' });
