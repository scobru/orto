Your workspace.
No server. No account.

ZenOS is a decentralized personal workspace: encrypted notes, calendar, bookmarks, tasks, contacts, secrets, files and a public blog, all stored in the ZEN P2P graph under one cryptographic identity derived from your username and password.

Open ZenOS Web Install CLI / SDK

What it does

🔒 Vault~pub/vault

Markdown notes, tags, checklists. AES-GCM-256 encrypted in your browser; relays see only ciphertext.

📋 Tasks~pub/tasks

Encrypted Kanban board with columns, priorities, due dates, and note cross-links.

📅 Calendar~pub/calendar

Encrypted events and agenda, linked to Vault notes.

🔖 Bookmarks~pub/bookmarks

Private library with folders and tags. Import/export Brave, Chrome, Firefox HTML.

👥 Contacts~pub/contacts

Encrypted address book with tags and a ZEN key per contact. Import and export vCard (.vcf).

🔑 Secrets~pub/secrets

Passwords, API keys and secure notes, encrypted before they leave your browser. Hidden by default, with a password generator.

📁 Files~pub/files

Encrypted file storage on IPFS. Needs a Delay relay and its token; the app checks the relay type for you.

🪶 smollog~pub/posts

Public Markdown blog, ECDSA-signed so readers can verify the author.

Serverless: static HTML + secp256k1 keys + ZEN relays for sync. Same login gives the same identity in ZenOS Web, CLI, smollog and FID. AI agents can read and write the same data through the SDK.

Install

Web: nothing to install. Open the app, log in with username + password. First login creates your identity.

CLI / SDK (Node 18+):

git clone https://github.com/scobru/zenos.git
cd zenos
node cli.js identity --user "alice" --pass "secret"

Self-host the web app: it is plain static files. Serve the folder anywhere (GitHub Pages, Vercel, Netlify):

git clone https://github.com/scobru/zenos-web.git
npx serve zenos-web

Username and password are case-sensitive and are the only key. Lose them, lose the data. No recovery.

Use

  1. Log in on the web app. Write notes, add events, import bookmarks and contacts, store passwords, upload files, publish posts.
  2. Script it with the CLI:
node cli.js vault-write --user alice --pass secret \
  --title "Idea" --body "- [ ] ship it" --cat research
node cli.js vault-read  --user alice --pass secret --query idea
node cli.js bookmarks-import --user alice --pass secret --file bookmarks.html
node cli.js contacts-import --user alice --pass secret --file contacts.vcf
node cli.js secret-add --user alice --pass secret --name GitHub --generate
ZENOS_STORAGE_TOKEN=... node cli.js file-upload --user alice --pass secret --file photo.png
node cli.js blog-publish --user alice --pass secret \
  --title "Hello" --content "First post" --tags "zenos,p2p"
node cli.js blog-read --alias alice

Or the JavaScript SDK:

import ZenOS from './zenos.js';
const os = new ZenOS();
await os.login('alice', 'secret');
await os.writeVaultNote({ title: 'Hi', body: 'Encrypted.', cat: 'logs' });
await os.writeCalendarEvent({ title: 'Standup', start: Date.now() + 36e5 });

Agents: see llm.txt for the integration guide.

Relays

Data syncs through ZEN relays (WebSocket peers). Defaults: wss://delay.scobrudot.dev/zen (author's personal relay, best-effort, no SLA) and wss://zen.akao.io:8420/zen (public network). For anything serious, run your own:

node cli.js vault-read --user alice --pass secret \
  --relay "wss://relay.example.com/zen" --no-default-relays

File storage only works on a Delay relay (it adds IPFS next to the ZEN websocket). zen.akao.io is a plain ZEN relay and has none. Upload needs the Delay relay's admin token or API key, so on a relay you do not run, ask its operator. In the web app set it under Files → Token; it is stored encrypted with your key.

Relay operators see public keys, timestamps, paths and IPs, never vault contents. Guide: RELAYS.md.
