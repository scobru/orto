Your workspace.
Your server. Your data.

Orto is a self-hosted personal workspace: encrypted notes, calendar, bookmarks, an RSS reader, tasks, contacts, secrets, files, music and video, and a public blog, on one small Node server with a single SQLite file. Everything private is encrypted in your browser with a key derived from your username and password; the server only stores ciphertext.

Run your server Install CLI / SDK

What it does

🔒 Vaultvault

Markdown notes, tags, checklists. AES-GCM-256 encrypted in your browser; the server sees only ciphertext.

📋 Taskstasks

Encrypted Kanban board with columns, priorities, due dates, and note cross-links.

📅 Calendarcalendar

Encrypted events and agenda, linked to Vault notes.

🔖 Bookmarksbookmarks

Private library with folders and tags. Import/export Brave, Chrome, Firefox HTML.

📡 Feedsfeeds

Follow blogs and news over RSS or Atom. The list is encrypted, OPML in and out; articles are fetched live, never stored.

👥 Contactscontacts

Encrypted address book with tags and an optional Orto username per contact. Import and export vCard (.vcf).

🔑 Secretssecrets

Passwords, API keys and secure notes, encrypted before they leave your browser. Hidden by default, with a password generator.

📁 Filesfiles

Upload any file, in folders. Encrypted in the browser (big files in chunks), stored on your server's disk, with a per-user quota.

🖼️ Photosfiles

Thumbnail gallery of your images with albums, encrypted like everything else. Upload from any device with a browser.

🎵 Mediafiles

Play your own music and video while they stream: decrypted in your browser chunk by chunk, with playlists and seeking.

🔗 Public links/s/<id>#key

Share a note or file with anyone. The key lives only in the link, so the server cannot read what you share. Revoke any time.

💾 Backupexport / import

Export everything in one file, import it anywhere: that is also how you move to another server. Plus node server.js backup.

🪶 Blogposts

Public Markdown blog at /blog/<username> with an RSS feed at /feed.xml, e.g. orto.scobrudot.dev/blog/scobru.

One login works in the web app, the CLI and the SDK. AI agents can read and write the same data through the SDK.

Install

Needs Node 22.5+ (built-in SQLite). No npm packages.

git clone https://github.com/scobru/orto.git
cd orto && npm start          # http://127.0.0.1:8787

Open the URL, pick a username and password; the app offers to create the account on first login. Put it behind HTTPS (Caddy, nginx) before exposing it.

The password is the only key to your data. Lose it, lose the data. No recovery.

Use

  1. Log in on your server's web app. Write notes, add events, import bookmarks and contacts, store passwords, upload files, publish posts.
  2. Script it with the CLI:
node cli.js vault-write --user alice --pass secret \
  --title "Idea" --body "- [ ] ship it" --cat research
node cli.js vault-read  --user alice --pass secret --query idea
node cli.js bookmarks-import --user alice --pass secret --file bookmarks.html
node cli.js contacts-import --user alice --pass secret --file contacts.vcf
node cli.js secret-add --user alice --pass secret --name GitHub --generate
node cli.js file-upload --user alice --pass secret --file photo.png
node cli.js blog-publish --user alice --pass secret \
  --title "Hello" --content "First post" --tags "orto,notes"
node cli.js blog-read --alias alice

Or the JavaScript SDK:

import Orto from './orto.js';
const os = new Orto();   // default server: https://orto.scobrudot.dev
await os.login('alice', 'secret');
await os.writeVaultNote({ title: 'Hi', body: 'Encrypted.', cat: 'logs' });
await os.writeCalendarEvent({ title: 'Standup', start: Date.now() + 36e5 });

Agents: see llm.txt for the integration guide.

Server

One file, server.js: an HTTP API, live updates (SSE), SQLite storage and an uploads folder. Back up the data/ folder and you have backed up everything. Settings are environment variables (PORT, ORTO_DATA, ORTO_REGISTRATION=closed, ORTO_QUOTA, ...), listed in the README.

The operator sees usernames, record ids, timestamps, sizes and IPs, never contents.
