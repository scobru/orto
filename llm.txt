# ZenOS — LLM & Autonomous Agent Integration Guide (llm.txt)

> **Instructions for AI Agents, LLMs, and Automation Scripts:**
> ZenOS is a decentralized, zero-backend, multi-app operating system powered by **ZEN** (peer-to-peer graph database & cryptographic identity).
> You do NOT need a browser, headless browser, or UI to interact with ZenOS.
> Any autonomous agent given a user's master credentials (`username` and `password`) can derive the exact same cryptographic keypair (`pair`), connect directly to the decentralized P2P graph overlay, and read, write, or synchronize across all ZenOS app nodes (private encrypted notes in ZenVault, encrypted calendar events, private curated bookmarks, public articles in smollog, and future modules).

---

## 1. Vision & Architecture

ZenOS unifies a user's digital life under a **single sovereign cryptographic identity** (`pair.pub`):

```
                     ┌────────────────────────────────────────┐
                     │          Master Credentials            │
                     │         username + password            │
                     └──────────────────┬─────────────────────┘
                                        │ ZEN.pair(null, { seed })
                                        ▼
                     ┌────────────────────────────────────────┐
                     │       Unified Public Key (Identity)    │
                     │                 ~{pub}                 │
                     └──────────────────┬─────────────────────┘
                                        │
         ┌──────────────────────────────┼──────────────────────────────┬──────────────────────────────┐
         │                              │                              │                              │
         ▼                              ▼                              ▼                              ▼
  ┌──────────────┐              ┌──────────────┐              ┌──────────────┐              ┌──────────────┐
  │   ZenVault   │              │   Calendar   │              │  Bookmarks   │              │   smollog    │
  │ ~{pub}/vault │              │~{pub}/calenda│              │~{pub}/bookmar│              │ ~{pub}/posts │
  │  [AES-GCM]   │              │  [AES-GCM]   │              │  [AES-GCM]   │              │   [Signed]   │
  └──────────────┘              └──────────────┘              └──────────────┘              └──────────────┘
```

- **Zero Central Server**: All data lives across a peer-to-peer graph overlay (GunDB / ZEN protocol).
- **Zero-Knowledge Private Nodes (`/vault`, `/calendar`, `/bookmarks`, `/tasks`)**: Payloads are encrypted with AES-GCM-256 before leaving the client. Relays only relay blind ciphertexts.
- **Verifiable Public Nodes (`/posts`)**: Blog entries are signed using ECDSA (secp256k1) and readable by anyone knowing the author's public key or alias.
- **Cross-App Synergies for AI**: An AI agent can read notes in ZenVault, link them to Calendar events and Tasks, curate Bookmarks, and publish reports directly to smollog!

## 2. Dependencies & Initialization

### Loading ZEN Library
```javascript
// ESM / Browser / Deno / Node (ESM)
import ZEN from 'https://cdn.jsdelivr.net/gh/scobru/zen@main/zen.min.js';
```

### Default P2P WebSocket Relays
ZenOS connects to these relays by default:
```json
[
  "wss://delay.scobrudot.dev/zen",
  "wss://zen.akao.io:8420/zen"
]
```

> **DISCLOSURE**: `wss://delay.scobrudot.dev/zen` is the **personal relay of the ZenOS author (scobru)**, running Delay / shogun-relay. It is best-effort (no SLA, no uptime or retention guarantee). `wss://zen.akao.io:8420/zen` is a public relay of the upstream ZEN network.

### Custom Relays
```bash
# CLI: add to defaults
node cli.js vault-read --user U --pass P --relay "wss://relay.example.com/zen"
# CLI: only custom relays
node cli.js vault-read --user U --pass P --relay "wss://relay.example.com/zen" --no-default-relays
# Env (applies to every call)
ZENOS_RELAYS="wss://relay.example.com/zen" ZENOS_ONLY_CUSTOM_RELAYS=true node cli.js vault-read --user U --pass P
```

```javascript
import ZenOS from './zenos.js';
new ZenOS({ extraPeers: ['wss://relay.example.com/zen'] });                          // defaults + custom
new ZenOS({ extraPeers: ['wss://relay.example.com/zen'], useDefaultRelays: false }); // custom only
new ZenOS({ peers: ['wss://relay.example.com/zen'] });                               // full replacement
```

## 3. Cryptographic Key Derivation

ZenOS uses deterministic key derivation (FID standard) so that an agent and the user in the browser produce the **identical keypair**:

```javascript
import { deriveMasterPair } from './identity.js';
const pair = await deriveMasterPair(ZEN, username, password);
// = ZEN.pair(null, { seed: username.trim() + ':' + password.trim() })
```

The resulting `pair` object contains:
- `pair.pub`: User's public identity (e.g. `048rVeyEIjxgGPXFHe47kYg9J8OyZflEC2W7RrUTPhVX0`)
- `pair.priv`: User's private signing and decryption key (base62 scalar)
- `pair.address`: EVM compatible checksummed address (e.g. `0x2F256...`)

> **CRITICAL RULE FOR ALL WRITES**: When calling `.put()` on any node under `~pair.pub`, you **MUST** pass `{ authenticator: pair }` as the options argument.

## 4. Node Specification: ZenVault (Encrypted Notes)

### Path
`zen.get('~' + pair.pub).get('vault')`

### Note Schema
| Field | Type | Encrypted? | Description |
|---|---|---|---|
| `title` | `string` | **YES** | Encrypted title (e.g. `🐻 Research Notes`) |
| `body` | `string` | **YES** | Encrypted Markdown content |
| `cat` | `string` | **YES** | Category or primary tag (e.g. `work`, `ai`) |
| `pinned` | `boolean` | **NO** | `true` if pinned |
| `trash` | `boolean` | **NO** | Soft-delete flag |
| `timestamp` | `number` | **NO** | Unix epoch in milliseconds (`Date.now()`) |
| `encrypted` | `boolean` | **NO** | Always `true` |

### SDK Methods
```javascript
const res = await os.writeVaultNote({ title, body, cat, pinned, soul });
const note = await os.getVaultNote(soul);
const notes = await os.readVaultNotes(timeoutMs);
const del = await os.deleteVaultNote(soul);
```

## 5. Node Specification: Calendar (Encrypted Events & Links)

### Path
`zen.get('~' + pair.pub).get('calendar')`

### Event Schema (Encrypted Payload)
| Field | Type | Description |
|---|---|---|
| `title` | `string` | Event title (e.g. `Dentist Appointment`) |
| `start` | `number` | Start time in milliseconds epoch |
| `end` | `number` | End time in milliseconds epoch |
| `allDay` | `boolean` | `true` for all-day event |
| `notes` | `string` | Optional description or meeting agenda |
| `location` | `string` | Optional physical location or video link |
| `links` | `Array<{kind: 'note'\|'bookmark', soul: string}>` | Bidirectional graph references |

### SDK Methods
```javascript
const ev = await os.writeCalendarEvent({ title, start, end, allDay, notes, location, soul });
const single = await os.getCalendarEvent(soul);
const list = await os.readCalendarEvents({ from, to, timeoutMs });
const del = await os.deleteCalendarEvent(soul);

// Graph links
await os.linkToEvent(eventSoul, { kind: 'note', soul: noteSoul });
await os.unlinkFromEvent(eventSoul, { kind: 'note', soul: noteSoul });
const linkedEvents = await os.eventsFor({ kind: 'note', soul: noteSoul });
const linkedNotes = await os.notesForEvent(eventSoul);
```

## 7. Node Specification: Tasks & Kanban (Encrypted Projects & Tasks)

`zen.get('~' + pair.pub).get('tasks')`

## 10. Full Autonomous Agent Pipeline Example

```javascript
import ZenOS from './zenos.js';

async function runAutonomousWorkflow() {
  const os = new ZenOS();
  await os.login('scobru', 'your_secure_password');
  console.log('ZenOS Agent authenticated for:', os.pub);

  // 1. Fetch research from Vault
  const notes = await os.readVaultNotes(4000);
  console.log(`Found ${notes.length} vault notes.`);

  // 2. Schedule follow-up calendar event & link first note
  if (notes.length > 0) {
    const ev = await os.writeCalendarEvent({
      title: 'Review: ' + notes[0].title,
      start: Date.now() + 86400000,
      notes: 'Automated follow-up scheduled by AI agent.'
    });
    await os.linkToEvent(ev.soul, { soul: notes[0].soul });
    console.log('Scheduled and linked event:', ev.soul);
  }

  // 3. Publish public summary post to smollog
  const blogResult = await os.publishBlogPost({
    title: '🤖 Agent Dispatches: Synchronizing with ZenOS',
    content: '### Autonomous Sync Complete\n\nZenOS connects our decentralized vault with our public voice.\n\n- Encrypted storage: Secure\n- Calendar graph: Linked\n- Public journal: Active',
    tags: ['zenos', 'agent', 'p2p']
  });
  console.log('Published to smollog:', blogResult.id);

  // 4. Log execution event in private Vault
  await os.writeVaultNote({
    title: '🤖 Agent Log: Synced with smollog',
    body: `Successfully published article ${blogResult.id} at ${new Date().toISOString()}`,
    cat: 'agent-logs'
  });
  console.log('Saved execution record in ZenVault.');
}
```

## 11. Best Practices for Agents

1. **Always use `{ authenticator: pair }` on `.put()`**: The P2P relay requires cryptographic proof of authority to modify any child of `~pair.pub`.
2. **Local snapshot cache**: In Node.js, `ZenOS` automatically maintains a persistent encrypted snapshot at `~/.zenos/cache.json`, enabling warm reads in <350ms.
3. **Graceful degradation**: Wrap `ZEN.decrypt` in `try / catch` to ignore old, corrupted, or non-encrypted legacy nodes.
4. **Deterministic identity**: Username and password are both case-sensitive (FID derivation). Never change their casing without user confirmation.
5. **Paginating large queries**: Nodes with thousands of records should be queried with `--count` (`-c`) to check total size, and paginated with `--limit` (`-n`) and `--page` (`-p`) or formatted with `--table` (`-t`) to prevent overwhelming terminal output and agent context windows.
