# ZenOS Web / Vault — LLM & Autonomous Agent Integration Guide (llm.txt)

> **Instructions for AI Agents, LLMs, and Automation Scripts:**
> You do NOT need a browser, headless browser, or UI to interact with ZenOS.
> You can read, write, update, and search notes directly inside the decentralized P2P graph database (ZEN / GunDB) using deterministic cryptographic keys derived from user credentials (`username` and `password`).

---

## 1. Core Architecture & Philosophy

ZenOS Web (formerly ZenVault) is the official web desktop and graphical interface for ZenOS. Its **Vault** module is a **zero-knowledge, end-to-end encrypted (E2EE) decentralized private vault**.
- **No central server or database**: Data lives across a peer-to-peer graph overlay.
- **Relays are blind routers**: All content payload (`title`, `body`, `cat`) is encrypted with AES-GCM 256 before touching the network. Relays only relay encrypted ciphertexts.
- **Deterministic Keypairs**: An agent given `username` and `password` derives the exact same cryptographic keypair (`pair`) as the human user in the browser.

## 3. Cryptographic Key Derivation

ZenVault uses the FID derivation (`identity.js` from scobru/fid), shared with FID, smollog and ZenOS, so one login is one `pub` everywhere: `ZEN.pair(null, { seed: alias.trim() + ':' + passphrase.trim() })`. Both parts are case-sensitive:

```javascript
import { deriveMasterPair } from 'https://cdn.jsdelivr.net/gh/scobru/fid@7887fc3468a77943da8ef18a70c3936d1dc45a2a/identity.js';
const pair = await deriveMasterPair(ZEN, username, password);
```

The resulting `pair` object contains:
- `pair.pub`: User's public key (hex identity)
- `pair.priv`: User's private signing key
- `pair.epub`: Public key for ECDH encryption
- `pair.epriv`: Private key for ECDH encryption

## 4. Graph Path & Data Schema

### Graph Root Path
All user notes are stored under the authenticated root path:
```
zen.get('~' + pair.pub).get('vault')
```

### Individual Note Key (Soul)
Each note has a unique identifier:
```javascript
const noteId = 'vault-' + Date.now() + '-' + Math.random().toString(36).substring(7);
const noteNode = zen.get('~' + pair.pub).get('vault').get(noteId);
```

### Note Payload Specification
All sensitive fields **MUST be encrypted** with `ZEN.encrypt(text, pair)`.

| Field | Type | Encrypted? | Description |
|---|---|---|---|
| `title` | `string` | **YES** | Encrypted note title (e.g. `🐻 Research Notes`) |
| `body` | `string` | **YES** | Encrypted Markdown content |
| `cat` | `string` | **YES** | Category or primary tag (e.g. `work`, `research`, or `private`) |
| `timestamp` | `number` | **NO** | Milliseconds Unix Epoch (`Date.now()`) |
| `pinned` | `boolean` | **NO** | `true` if note is pinned to top, `false` otherwise |
| `trash` | `boolean` | **NO** | `true` if note is soft-deleted, `false` otherwise |
| `encrypted` | `boolean` | **NO** | Always `true` |

## 5. Bear Markdown & Content Formatting for Agents

When generating content for the user's vault, follow Bear 2 style conventions:

1. **Title with Emojis**: Start titles with a fitting emoji:
   `🐻 Project Alpha`, `💡 Startup Idea`, `💻 Rust Microservice`, `🍕 Favorite Recipes`.
2. **Hashtags (`#tag` / `#category/subtag`)**:
   Include hashtags anywhere in the body or title (e.g. `#work`, `#personal/finance`, `#todo`). ZenVault automatically indexes them in the sidebar tag tree.
3. **Interactive Task Checklists**:
   Use standard `- [ ] task` and `- [x] completed task`. ZenVault renders them as interactive checkboxes in the UI.
4. **Thumbnail Images**:
   Include markdown images `![Alt text](https://images.unsplash.com/...)`. ZenVault automatically extracts the first image and displays an inline preview thumbnail in the note card list!
5. **Tables**:
   Format structured data using clean Markdown tables:
   ```markdown
   | Parameter | Type | Default |
   |---|---|---|
   | timeout | number | 5000 |
   ```

## 6. Complete Autonomous Agent Code Examples

### Example 1: Write a New Encrypted Note (Node / ESM / Deno)

```javascript
import ZEN from 'https://cdn.jsdelivr.net/gh/scobru/zen@main/zen.min.js';

async function writeNoteToVault({ username, password, title, body, category = 'agent', pinned = false }) {
  // 1. Initialize P2P connection to relays
  const zen = new ZEN({
    peers: [
      "wss://delay.scobrudot.dev/zen",
      "wss://zen.akao.io:8420/zen"
    ]
  });

  // 2. Derive master keypair from user credentials
  const pair = await deriveMasterPair(ZEN, username, password); // see section 3

  // 3. Encrypt payload
  const encTitle = await ZEN.encrypt(title, pair);
  const encBody = await ZEN.encrypt(body, pair);
  const encCat = await ZEN.encrypt(category, pair);

  // 4. Generate unique note key
  const noteId = 'vault-' + Date.now() + '-' + Math.random().toString(36).substring(7);

  const payload = {
    title: encTitle,
    body: encBody,
    cat: encCat,
    pinned: !!pinned,
    trash: false,
    timestamp: Date.now(),
    encrypted: true
  };

  // 5. Store and propagate to decentralized P2P graph
  return new Promise((resolve, reject) => {
    zen.get('~' + pair.pub).get('vault').get(noteId).put(payload, (ack) => {
      if (ack && ack.err) {
        reject(new Error("P2P storage failed: " + ack.err));
      } else {
        resolve({ noteId, status: "success", timestamp: payload.timestamp });
      }
    }, { authenticator: pair });
  });
}

// Usage:
// await writeNoteToVault({
//   username: "scobru",
//   password: "mypassword123",
//   title: "🤖 Agent Summary: Market Analysis",
//   category: "finance",
//   body: "### Executive Summary\nAnalysis complete. #finance #automated\n- [x] Gather data\n- [ ] Deploy strategy"
// });
```

### Example 2: Read & Decrypt All Notes from Vault

```javascript
import ZEN from 'https://cdn.jsdelivr.net/gh/scobru/zen@main/zen.min.js';

async function readAllNotes({ username, password, timeoutMs = 4000 }) {
  const zen = new ZEN({
    peers: [
      "wss://delay.scobrudot.dev/zen",
      "wss://zen.akao.io:8420/zen"
    ]
  });

  const pair = await deriveMasterPair(ZEN, username, password); // see section 3
  const notes = [];

  return new Promise((resolve) => {
    const timer = setTimeout(() => {
      resolve(notes);
    }, timeoutMs);

    zen.get('~' + pair.pub).get('vault').map().once(async (node, id) => {
      if (!node) return; // deleted node

      try {
        const title = await ZEN.decrypt(node.title, pair);
        const body = await ZEN.decrypt(node.body, pair);
        const cat = await ZEN.decrypt(node.cat, pair);

        notes.push({
          id,
          title,
          body,
          cat,
          pinned: !!node.pinned,
          trash: !!node.trash,
          timestamp: node.timestamp
        });
      } catch (e) {
        // Skip un-decryptable or corrupted nodes
      }
    });
  });
}
```

### Example 3: Append Content or Update Existing Note

```javascript
import ZEN from 'https://cdn.jsdelivr.net/gh/scobru/zen@main/zen.min.js';

async function appendToNote({ username, password, noteId, textToAppend }) {
  const zen = new ZEN({
    peers: ["wss://delay.scobrudot.dev/zen", "wss://zen.akao.io:8420/zen"]
  });

  const pair = await deriveMasterPair(ZEN, username, password); // see section 3
  const noteRef = zen.get('~' + pair.pub).get('vault').get(noteId);

  return new Promise((resolve, reject) => {
    noteRef.once(async (node) => {
      if (!node) return reject(new Error("Note not found"));

      const currentTitle = await ZEN.decrypt(node.title, pair);
      const currentBody = await ZEN.decrypt(node.body, pair);
      const currentCat = await ZEN.decrypt(node.cat, pair);

      const updatedBody = currentBody + "\n\n" + textToAppend;
      const encBody = await ZEN.encrypt(updatedBody, pair);

      noteRef.put({
        ...node,
        body: encBody,
        timestamp: Date.now()
      }, (ack) => {
        if (ack && ack.err) reject(new Error(ack.err));
        else resolve({ status: "updated", noteId });
      }, { authenticator: pair });
    });
  });
}
```

## 8. File Storage (Delay relay + IPFS)

The web app has a **Files** view. Files are uploaded to IPFS through a **Delay** relay (https://github.com/scobru/delay), not through plain ZEN relays. Agents should use the ZenOS SDK/CLI (`file-upload`, `file-list`, `file-download`, `os.uploadFile`, see https://github.com/scobru/zenos/blob/main/llm.txt section 9):
- Detect Delay: `GET <relay origin>/api/v1/system/health` returns `{ "success": true, "message": "Delay is running" }`.
- Upload: `POST /api/v1/ipfs/upload` with `Authorization: Bearer <admin token or delay-api-* key>`; ask the user for the token.
- Encrypted index per file at `~{pub}/files/<cid>` (`ZEN.encrypt({cid,name,size,encrypted,addedAt}, pair)`).

## 8b. Contacts and Secrets

The web app has **Contacts** (`~{pub}/contacts`) and **Secrets** (`~{pub}/secrets`) views. Both store the whole record as `ZEN.encrypt(record, pair)` in a `data` field. Agents should use the ZenOS SDK/CLI (`writeContact`, `writeSecret`, `contact-*`, `secret-*`; see https://github.com/scobru/zenos/blob/main/llm.txt section 9b). Never print or log secret values unless the user asked.

## 8c. Calendar, Bookmarks, Tasks and Blog

The web app also has Calendar, Bookmarks, Tasks and Blog views. Agents should use the ZenOS SDK/CLI; full schemas and CLI commands: https://github.com/scobru/zenos/blob/main/llm.txt (sections 5-8).

| Module | Path | Encryption | Core fields | SDK |
|---|---|---|---|---|
| Calendar | `~{pub}/calendar` | AES-GCM | `title, start, end, allDay, notes, location, links[]` | `writeCalendarEvent`, `readCalendarEvents`, `deleteCalendarEvent` |
| Bookmarks | `~{pub}/bookmarks` | AES-GCM | `url, title, folder, tags[], addedAt` | `writeBookmark`, `readBookmarks`, `updateBookmark`, `importBookmarksHtml` |
| Tasks | `~{pub}/tasks` | AES-GCM | `title, status, priority, desc, dueDate, tags[], assignee, column, links[]` | `writeTask`, `readTasks`, `updateTask`, `deleteTask` |
| Blog (smollog) | `~{pub}/posts` | none (public, signed) | `id, title, content, tags, authorAlias, authorPub, createdAt, updatedAt, deleted` | `publishBlogPost`, `readBlogPosts`, `deleteBlogPost`, `registerAlias` |

## 9. Troubleshooting & Best Practices for Agents

1. **Wait for P2P propagation**: GunDB/ZEN propagates asynchronously over WebSockets. Always wrap `.put()` in a Promise and allow 500-1500ms before disconnecting process.
2. **Deterministic pairs**: Username and password are both case-sensitive. Data written under the earlier schemes (smollog PBKDF2, plain `username + password`) is copied to the FID identity by the web app at login.
3. **No server error codes**: GunDB uses `{ ack: { err: ... } }` callbacks rather than HTTP 4xx/5xx status codes.
4. **Idempotence**: Note IDs can be generated using a consistent slug (e.g. `vault-daily-2026-10-03`) if you want the agent to overwrite or maintain a single daily note.
