# Orto (self-hosted) — LLM & agent integration guide

Orto is a self-hosted personal workspace. One Node server (`server.js`: HTTP API + SQLite file + upload folder) and a dependency-free client SDK (`orto.js`, Node >= 18 and browsers). No P2P network.

## Architecture

```
username + password --PBKDF2 (210k, SHA-256, salt "zenos:v1:<username lowercased>", 512 bits)--+
   first 256 bits -> AES-GCM key   (stays on the client, encrypts every private record)
   last  256 bits -> auth secret   (sent to the server, stored only as sha256 hash)
client --HTTPS--> server.js --> data/orto.db (users, sessions, records) + data/files/<user>/<id>
```

- Record = `(user, collection, soul)` -> JSON. Private collections store `{ data: "e1.<base64 iv+ciphertext>", encrypted: true }`; the whole object is inside `data`. The server adds `updatedAt`.
- `posts` (public blog) is stored in clear and readable without login.
- Souls are client-chosen ids (`vault-…`, `cal-…`, `task-…`, `ct-…`, `sc-…`, `bm-<hash of url>`, file id from the server).
- Collections: `vault`, `calendar`, `tasks`, `bookmarks`, `contacts`, `secrets`, `feeds` (followed RSS/Atom), `files` (encrypted index of uploads), `posts`.

## SDK

```js
import Orto from './orto.js';
const os = new Orto();   // server: option or env ORTO_SERVER; default https://orto.scobrudot.dev; '' = same origin in a browser
await os.login(username, password, { create: false });        // create:true registers; error.status 404 = unknown user, 401 = wrong password
os.pub                                                        // lowercase username = public handle
```

Every collection follows the same shape (`onX(cb)` replays existing records, then streams changes; cb(entry, soul, isDeleted); returns an unsubscribe fn):

| App | write | read / get | delete | live |
|---|---|---|---|---|
| Vault | `writeVaultNote({title, body, cat, pinned, soul})` | `readVaultNotes()`, `getVaultNote(soul)` | `deleteVaultNote(soul)` | `onVaultNote` |
| Calendar | `writeCalendarEvent({title, start, end, allDay, notes, location, links, soul})` | `readCalendarEvents({from, to})`, `getCalendarEvent(soul)` | `deleteCalendarEvent(soul)` | `onCalendarEvent` |
| Tasks | `writeTask({title, status, priority, desc, dueDate, tags, assignee, column, links, soul})`, `updateTask(soul, patch)` | `readTasks({status, priority, tag, query})`, `getTask(soul)` | `deleteTask(soul)` | `onTask` |
| Bookmarks | `writeBookmark({url, title, folder, tags})`, `importBookmarksHtml(html)`, `updateBookmarks([{soul, folder?, title?, tags?}])` | `readBookmarks({folder, query})`, `getBookmark(soul)`, `exportBookmarksHtml()` | `deleteBookmark(soul)` | `onBookmark` |
| Contacts | `writeContact({name, emails, phones, org, notes, tags, pub, soul})`, `importContactsVcf(text)` | `readContacts({query, tag})`, `getContact(soul)`, `exportContactsVcf()` | `deleteContact(soul)` | `onContact` |
| Feeds | `addFeed(url, {title, folder})` (same URL = same subscription), `importFeedsOpml(xml)` | `readFeeds()`, `fetchFeed(url)` -> `{title, link, items: [{id, title, link, date, summary, content}]}` (HTML in `summary`/`content`: sanitize), `findFeed(url)` (also accepts a web page that advertises its feed) -> `{url, feed}`, `exportFeedsOpml()` | `markFeedRead(soul, readAt)`, `deleteFeed(soul)` | `onFeed` |
| Secrets | `writeSecret({name, kind, username, secret, url, notes, tags, soul})` | `readSecrets({query, kind, tag})`, `getSecret(soul)` | `deleteSecret(soul)` | `onSecret` |
| Files | `uploadFile(bytes, name, {encrypt = true, folder, album, playlist})` -> `{id, name, size, encrypted, addedAt, folder?, album?, playlist?}`; `uploadFileChunked(blobOrBytes, name, {type, folder, album, playlist, onProgress})` (encrypted 1 MiB chunks, constant memory) | `listFiles()`, `downloadFile(id)` -> Uint8Array, `readFileRange(id, start, end)` (only the needed chunks), `fileGroups()` -> `{folders, albums, playlists}` | `moveFile(id, {folder, album, playlist})` ('' clears), `addFileGroup('folder'\|'album'\|'playlist', name)`, `renameFileGroup(kind, from, to)` ('' removes) | `deleteFile(id)` |
| Blog | `publishBlogPost({title, content, tags, id, createdAt})` | `readBlogPosts(username?)`, `getBlogPost(id, username?)` | `deleteBlogPost(id)` | `onPost(username, cb)` |

Links: `linkToEvent / unlinkFromEvent(eventSoul, {kind, soul})`, `linkToTask / unlinkFromTask`, `eventsFor({kind, soul})`, `tasksFor({kind, soul})`, `notesForEvent(eventSoul)`. `kind` is `note | bookmark | event | task`. Links live inside the encrypted record.

Sharing: `shareNote(soul)`, `shareFile(id)` -> `{id, url}` where url = `<server>/s/<id>#<key>` (key never reaches the server); `listShares()`, `unshare(id)`; `readShare(url)` (named export, no login). Account: `changePassword(new)`, `exportAll({files})` -> plain JSON object, `importAll(obj)`. `uploadFile(bytes, name, {encrypt, type, thumb, addedAt})` keeps `type` (MIME) and `thumb` (small data: URL) in the encrypted index.

Server backup: `node server.js backup <folder>`.

Low level: `os.encrypt(value)`, `os.decrypt(cipher)`, `os.put(collection, soul, obj)` (encrypts then stores), `os.resolveAlias(username)`, `os.close()`.

Notes:
- Bookmark soul = hash of the URL, so the same URL is never stored twice.
- Search and date filters run client-side (fields are encrypted), after downloading the collection.
- `uploadFile` encrypts the whole file in memory (AES-GCM, base64 inside the ciphertext): fine for documents and photos. Use `uploadFileChunked` for big files and media: 1 MiB chunks, each `iv(12) | AES-GCM | tag(16)` with authenticated data = file nonce + chunk index + chunk count, so memory stays constant and any byte range can be read with `readFileRange(id, start, end)` (a Range request for just the covering chunks). The index entry carries `chunked: {size, n, nonce}`; `downloadFile`, export/import, shares and `changePassword` handle both formats. `encrypt:false` uploads raw bytes (single blob).
- `folder` (nests with `/`), `album` and `playlist` are plain strings inside the encrypted index entry; empty ones live in one extra record of the `files` collection (soul `_groups`, no `id`, so `listFiles()` skips it).

## HTTP API

JSON everywhere; `Authorization: Bearer <token>`.

- `POST /api/register`, `POST /api/login` — body `{name, auth}` -> `{token, name}`. Errors: 400, 401, 403 (registration closed), 404 (unknown user), 409 (name taken), 429.
- `GET /api/c/:coll`, `GET|PUT|DELETE /api/c/:coll/:soul`
- `GET /api/events` — server-sent events: `{coll, soul, deleted, record?}`
- `POST /api/files` (raw body) -> `{id, size}`; `GET|PUT|DELETE /api/files/:id` (PUT replaces the blob; GET answers one `Range: bytes=a-b` with 206)
- chunked upload: `POST /api/files/begin` -> `{id}`; `PUT /api/files/:id/append` (raw chunk, header `X-Offset` = bytes stored so far, else 409; 413 over the size or quota limit and the file is cut back to the last good size, so retry) -> `{size}`; `POST /api/files/:id/finish[?replace=<existing id>]` -> `{id, size}`. Unfinished uploads are swept after a day.
- `POST /api/s` (JSON `{data}` = text share, raw bytes = file share) -> `{id}`; `DELETE /api/s/:id`; `GET /api/s/:id` is public (ciphertext only)
- `POST /api/password` `{auth, newAuth}` (after the client re-encrypted everything)
- `GET /api/u/:name` (exists?), `GET /api/u/:name/posts` (public, no auth), `GET /blog/:name` (HTML), `GET /blog/:name/feed.xml` (RSS 2.0 of the newest 50 public posts, no auth; links use `ORTO_PUBLIC_URL` or the request's Host)
- `GET /api/feed?url=<http(s) url>` (auth): the server fetches that feed and relays the XML (browsers cannot, CORS). 2 MB, 10 s, 3 redirects; private/loopback addresses are refused unless the server has `ORTO_FEEDS_PRIVATE=1`; 403 on the demo account
- admin panel (only when the server has `ORTO_ADMIN_PASS`, else 404): `POST /api/admin/login {pass}` -> `{token}` (separate from user tokens, 12 h); with it `GET|PUT /api/admin/settings` (`registration`, `maxUpload`, `quota`; `null` = env default), `GET /api/admin/users`, `DELETE /api/admin/users/:name`, `POST /api/admin/users/:name/logout`, `POST /api/admin/backup`. UI at `/admin`.
- pages: `/` and `/app/` the web app, `/about` the landing page, `/blog/:name`, `/s/:id`; `/models/*` is the optional add-on folder (`ORTO_MODELS`, default `<data>/models`)
- `GET /api/health`, `GET /api/config` (`{registration, maxUpload, demo?}`: `demo` is `{user, pass, hours}` when the server runs `ORTO_DEMO=1`, a public account that is reset with random fake data; sharing, posts and password change are 403 there)

## CLI

`node cli.js --help` lists everything. Credentials via `--user/--pass` or `ORTO_USER/ORTO_PASS`; server via `--server` or `ORTO_SERVER`.

## MCP

`mcp.js` (bin `orto-mcp`) is a stdio MCP server over the SDK: run it locally with `ORTO_SERVER`, `ORTO_USER`, `ORTO_PASS` (`claude mcp add orto -s user -e ... -- npx -y -p github:scobru/orto orto-mcp`; on Windows `cmd /c npx ...`; for Claude Desktop see README). It decrypts on the user's machine; never host it for other people (it would hold their password). Tools: `note_list|get|write`, `calendar_list`, `event_write`, `task_list|write|update`, `bookmark_list|add`, `contact_list|write`, `feed_list|add|read`, `blog_list|publish`, `file_list`, `delete {kind, id}`. `ORTO_MCP_READONLY=1` hides the writing tools; `ORTO_MCP_SECRETS=1` adds `secret_list|get`.

## Operating rules for agents

1. Never log or store the user's password; the same login always derives the same keys, and there is no recovery.
2. Treat decrypted content as private; only `posts` is public.
3. Before bulk changes (bookmark reorganisation, mass delete) export a backup and show the plan; deletes are permanent.
4. Check counts after bulk writes (`--count`).
5. Server operators can see usernames, record ids, timestamps, sizes and IPs, never contents.
