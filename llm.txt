# ZenOS Web — LLM & agent integration guide (llm.txt)

ZenOS Web is the browser front end of a self-hosted ZenOS server. It is a single static page (`app/index.html`) that imports the SDK (`app/zenos.js`); the server (github.com/scobru/zenos, `server.js`) hosts it and stores the data in SQLite.

You do not need a browser to work with the data. The full SDK / CLI / HTTP API reference lives in the zenos repo (`llm.txt`, `SKILL.md`). Short version:

```js
import ZenOS from './zenos.js';
const os = new ZenOS();   // default server: https://zenos.scobrudot.dev
await os.login(username, password);            // { create: true } the first time
await os.writeVaultNote({ title: 'Idea', body: '- [ ] ship it #todo', cat: 'research' });
const notes = await os.readVaultNotes();       // decrypted, pinned first then newest
await os.writeVaultNote({ soul: notes[0].soul, title: notes[0].title, body: notes[0].body + '\n- more', cat: notes[0].cat });  // update = same soul
await os.deleteVaultNote(notes[0].soul);
```

## Data model

Record = (user, collection, soul). Private collections (`vault`, `calendar`, `tasks`, `bookmarks`, `contacts`, `secrets`, `files`) hold `{ data: "e1.<ciphertext>" }`: the whole object is AES-GCM encrypted in the client with a key derived from username + password (PBKDF2). The server cannot read it. `posts` is the public blog (plaintext).

Vault note (inside the ciphertext): `{ title, body, cat, pinned, trash, timestamp }`. Body is Markdown; `#tags` in title/body become tags in the UI; `- [ ]` / `- [x]` are checklists.

## Rules for agents

1. Same username + password = same keys as the human. Never log or store the password; there is no recovery.
2. Update a note by writing with its existing `soul`; omit `soul` to create.
3. Deletes are permanent. Export backups before bulk changes.
4. Only the blog is public; never publish secrets.
